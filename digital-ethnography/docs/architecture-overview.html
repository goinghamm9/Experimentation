Product strategy & technical architecture

Digital Ethnographic Intelligence

An AI-native platform that continuously and ethically observes digital behaviour and online culture — and returns rigorous, cited, longitudinal ethnographic insight. Not another repository for interviews you already ran.

Posture Sovereignty-first, staged Surfaces Web app → API → MCP Kernel Ethics gate, 24 tests passing Status Architecture v1
01Positioning

Everyone analyses the sessions you ran. Nobody watches the field.

Dovetail, Marvin, Condens, Notably, Looppanel, UserTesting, dscout, Sprig, Maze — all run the same loop: collect a session a researcher deliberately ran → transcribe → AI-tag → synthesise → report. The unit of analysis is always a session you commissioned.

Two structural gaps follow from that, and they are the whole opportunity:

Gap 01

Observation vs. elicitation

No one productises observation of naturally-occurring digital behaviour — communities, forums, reviews, support logs, in-the-wild usage — as the primary substrate with research-grade provenance. dscout comes closest, and still needs recruited participants filming themselves.

Gap 02

Meaning vs. sentiment

Incumbents surface themes and polarity. Ethnography's value is meaning — norms, identity, rituals, discourse, how a culture shifts over time. Social listening owns the data but frames it as PR sentiment, not cited cultural insight.

The one-line position

The AI ethnographer that continuously and ethically observes digital behaviour and online culture, producing rigorous, cited, longitudinal cultural insight — exposed to humans (web app), systems (API), and other AI agents (MCP).

Against Dovetail/Marvin: they analyse what you bring; we watch the field. Against dscout: attack the ~$15K–$60K per-study floor and the weak B2B panel, and add the online-culture layer it doesn't have.

02Method

What makes it ethnography and not analytics

Credibility with senior and academic researchers is a moat in itself. The platform is organised around a named core methodology with a hard ethics backbone — not a generic "AI insights" pipeline.

Core method — Netnography (Kozinets)

Purpose-built for online communities, already procedural (so it maps cleanly to software), and it ships with an ethics protocol. Its stages become the Study object: initiation → investigation → immersion → data collection → interpretation → integration. Critically we implement its ethics steps too — consent thresholds, anonymisation, and quote cloaking so excerpts from small or vulnerable communities can't be reverse-searched back to a real person.

The ethics engine — AoIR IRE 3.0 + Contextual Integrity

Contextual Integrity (Nissenbaum) is the most operationally useful ethics theory available here: privacy is the appropriate flow of information relative to the norms of its original context. Repurposing a support-forum post into a research dataset is a context transgression even though nothing leaked. That becomes a literal gate in code, not a policy PDF.

Operating principle

Public ≠ consented. Scrapable ≠ usable. The greater the vulnerability of a community, the greater the obligation — regardless of how accessible the data is.

The paradigm landmine

Braun & Clarke's reflexive TA explicitly rejects inter-rater reliability and Cohen's κ as category errors — two researchers are supposed to code differently. But codebook-TA teams actively want κ. The product must support both epistemologies and never conflate them. Never market "reliable, objective automated coding." Get this wrong and you lose exactly the expert users whose endorsement you need.

The rigour loops

  1. Saturation loop. Track the rate of genuinely new codes against embedding novelty. Stop when it falls below threshold — a principled "we've analysed enough" and a hard cost governor.
  2. Reliability loop. N coders, then a dual metric: Cohen's/Fleiss' κ plus semantic similarity, which catches "same meaning, different label." Low agreement auto-escalates to a human. Scope corrected below.
  3. Reflection loop. Each coder self-critiques against source and codebook before submitting.
  4. Evaluator–optimiser loop. Theme narratives and code definitions are generated, critiqued against explicit criteria (grounded? distinct? ≥N supporting quotes?), refined.
  5. Adversarial verification. The skeptic must produce a refuting quote for each theme. Survivors are consensus-grounded; the rest are flagged. Primary hallucination defence.
  6. Human gates. Codebook approval before mass coding; low-agreement review; final sign-off. The human sees evidence, disagreement and confidence — never a smoothed answer. Every override is logged as eval data.

What makes it a learning organisation, not a static pipeline

Memory

Four layers

Working (per-study), episodic (past studies and human overrides), semantic (a living codebook that accumulates), procedural (versioned, eval-gated prompt assets).

Learning

Self-improving codebook

Code definitions refine from inter-coder disagreement and human overrides — proposed, human-approved, versioned. New studies bootstrap from prior codebooks only on explicit opt-in, because uncritical reuse imports prior bias.

Scaling

Dynamic spawning

The PI scales the coder pool to difficulty — more independent coders when disagreement is high, fewer when agreement is trivial. The team right-sizes itself.

Conflict

Structured debate

Disagreements aren't averaged away — they're argued out by a moderated debate agent mirroring real peer debriefing, with the human adjudicating persistent splits.

Amendment — models are not researchers

Adversarial research undercut the independence assumption behind the κ loop: LLM coder panels have severely correlated errors. Nine frontier judges across seven model families supplied only about two independent votes' worth of information; panel accuracy fell 8–22pp short of true independent voting; and the best single judge often matched or beat the panel.

So κ is demoted from a reliability claim to a disagreement-surfacing router — its job is to find the units a human must look at, not to certify correctness. Decorrelate deliberately by varying prompt frame, codebook framing and elicitation order, not merely model family. Never report inter-model κ as evidence of validity; only κ against a human gold codebook supports a quality claim. Treat high agreement as weak evidence — correlated models agree on their shared errors too — and treat disagreement as the strong, actionable signal.

Designing against the evidence

Peer-reviewed work (Ashwin, Chhabra & Rao, 2025) found LLM qualitative coding introduces systematic, non-random bias — errors correlate with subject characteristics, so they do not wash out with sample size. They bias conclusions in a consistent direction, silently distorting exactly the underrepresented voices research exists to surface. This is why multi-model coding, bias auditing and human gates are architecture, not features.

04Model fleet

Tiered routing — the utilisation that grows

Advertised context ≠ effective context: multi-fact retrieval degrades sharply past ~200K tokens. "Find every mention across the corpus" is a retrieval job, not a stuff-the-window job. Each task goes to the cheapest tier that can actually do it.

Embeddings
Clustering, dedup, retrieval, saturation novelty. Cheapest and highest volume — one index serves retrieval, clustering and saturation detection.
Small
PII, aspect-based sentiment, quote extraction, first-pass open coding against a fixed codebook. The bulk of token spend, with structured outputs.
Mid
Journey analysis and mid-complexity coding. The escalation target for low-confidence units.
Frontier
Axial and selective synthesis, thick description, adversarial critique, debate adjudication, cross-study reasoning. Low volume, high reasoning value.
Vision
Screenshots and session-replay frames. Prefer DOM/accessibility text where it exists — vision is the enricher, not the primary signal.

Routing is a cascade: a semantic router sends each unit to the cheapest capable tier; the small tier codes the bulk and emits confidence; only low-confidence or high-disagreement units escalate. Route by capability profile, never hardcoded model names — the frontier turns over roughly quarterly, and adding a model must be a config change, not a rebuild.

Cost discipline

Batch API (~50% off) for all non-interactive coding · prompt caching (~90% off cached reads) on the codebook and system prompt — these stack to roughly 95% · cascade keeps ~85% of units off the frontier · embeddings stop you paying to re-code saturated material. Cost scales with entries × participants × study length, not seats — which is why pricing must be usage-based, not per-seat.

06Data

First-party is the product; public data is licensed garnish

The legal reality makes DIY scraping a business-model time bomb. CFAA is mostly not the risk after hiQ v. LinkedIn and Meta v. Bright Data — breach of ToS is. And GDPR grants no "publicly available" exemption; CNIL fined KASPR €240K for scraping LinkedIn data.

Tier 1 · preferred

Official APIs

Stack Exchange (CC BY-SA), YouTube Data API, own-app store reviews, G2 paid, Discourse, GDELT.

Tier 2 · use with DPA

Licensed brokers

Bright Data, Apify, Reddit's commercial licence (~$0.24/1k calls, ~$12k/mo floor). Push legal risk to a vendor.

Tier 3 · prohibited

Never DIY-scrape

Anything logged-in or ToS-gated: X, TikTok (commercial barred), Discord (self-bots banned), Amazon, Glassdoor.

The connectors that actually matter

Weight the ontology toward qualitative voice. Highest signal-to-integration-effort first: the CDP (Segment) — connect once, fan out everything — and the conversation layer: support desks (Zendesk, Intercom, Front — the densest ethnographic text there is) and interview transcripts (Gong; Recall.ai as the meeting-bot aggregator normalising Zoom/Meet/Teams). Then surveys and NPS open-text, community (Discourse, Slack), product analytics (Amplitude, Mixpanel, PostHog), session replay (heavy PII — redaction critical), and CRM as the segmentation skeleton.

07Infrastructure

Sovereignty as discipline, not as a GPU bill

Full sovereignty on day one — self-hosted GPU fleet, self-hosted everything, SOC 2 controls — would consume a solo builder entirely on infrastructure instead of product. The resolution: choose self-hostable, portable, open-weight-compatible components so nothing forecloses sovereignty, while running managed services until a paying tenant contractually requires otherwise.

Evidence status — read before quoting any number

Every dive below was adversarially fact-checked, and three findings were corrected or refuted in the process. All dollar figures are directional and must be re-quoted before entering a financial model — the research environment had egress blocked to most vendor hosts, including every NVIDIA property.

The one-way doors

Everything else is reversible. These three cost days now and six months later:

  1. A model gateway abstraction from commit #1. Never call a provider SDK from application code. Route by capability profile, never by model name.
  2. A tenant→region pin in the data model, even while there is only one region. Retrofitting residency into a single-region schema is a migration from hell.
  3. Provenance edges from commit #1. The structure that produces citations is the same structure that makes erasure tractable.

Inference — the verdicts on Hermes and NIM

Don't build on it

Hermes

Hermes 4 is a Llama-3.1 derivative — 2024 base, 128K context, 8 languages, one hosted provider. The Llama licence would force "Built with Meta Llama 3.1" onto the UI of a governance-branded product. Both its selling points eroded: schema adherence is commoditised by constrained decoding, and low-refusal is matched by Gemma 4 / Qwen 3.5 without the liability of a model marketed as having no guardrails — acute when your moat is the ethics kernel and your inputs are attacker-influenceable.

Don't adopt it

NVIDIA NIM

The licensing cost could not be verified — all NVIDIA properties were egress-blocked for both researcher and fact-checker. Get a written quote. The verdict survives on checkable grounds: NIM LLM 2.0 is a wrapper around vLLM, and NIM ships with prefix caching disabled while vLLM ships with it enabled — so for a shared-codebook fan-out, default NIM is likely slower. Standardise on vLLM behind your own abstraction.

Retracted in verification

An earlier draft claimed SGLang's RadixAttention maps onto the N-coders-share-a-codebook pattern for a large throughput win. Refuted. vLLM's automatic prefix caching is on by default, so both engines already eliminate shared-prefix recompute — and an extreme prefix ratio collapses the gap rather than amplifying it. The real engine tweak is enabling vLLM's cascade attention, which is off by default.

Open-weight cascade instead: Qwen3-Embedding for retrieval · Qwen 3.5 27B / Gemma 4 26B for high-volume deductive coding · Qwen 3.5 122B / DeepSeek V4-Flash for inductive coding and synthesis · Mistral Large 3 + Apertus for the EU-sovereign SKU · frontier closed models via Bedrock EU for the hardest synthesis and adjudication.

EU residency, precisely

Anthropic first-party has no EU option at all — inference_geo accepts only global and us, and workspace geo is us-only and immutable. Bedrock EU and Vertex EU deliver GDPR-grade residency today without any GPU. But the trap: the Bedrock EU inference profile can route to Zurich and London — outside the EU/EEA. Only in-region endpoints are real residency, and an enterprise reviewer will find this.

The EU–US Data Privacy Framework survives but is under live CJEU appeal (C-703/25 P). Architect as if it will fall: EU tenant data never leaves the EEA by default.

The cheap sovereignty move

Self-host embeddings and PII redaction in your own VPC. That keeps the raw participant corpus off third-party infrastructure at trivial cost, while frontier reasoning runs on Bedrock EU. Most of the sovereignty value, a fraction of the burden — the right answer for a team of one.

A validity threat that outranks the cost analysis

Model retirement dates are confirmed exactly — Sonnet 3.7 and Haiku 3.5 retired 19 Feb 2026, Opus 3 on 5 Jan 2026, Opus 4.1 retiring 5 Aug 2026, with only ~60 days' notice guaranteed. Frontier deprecation cycles are incompatible with multi-year longitudinal ethnography: if the coder model changes mid-study, inter-model drift becomes confounded with the cultural change you are trying to measure. Longitudinal studies must pin a model version for the study's life — which is the strongest argument for self-hosted open weights on that path specifically. You control the weights, so the instrument stays constant.

Orchestration — Temporal outside, typed code inside

Do not make an agent framework the orchestration backbone. langgraph-api — the production server — is Elastic License 2.0, which prohibits providing it to third parties as a hosted service. That directly conflicts with a multi-tenant SaaS plus public API plus MCP roadmap. (The LangGraph library is MIT and genuinely good; the server is the problem.) A March 2026 checkpointer deserialization RCE chain settles it for a kernel holding participant data.

The seam

Workflow = the study — durable, versioned, tenant-scoped, human-gated.
Activity = exactly one bounded, idempotent, cost-attributed LLM or tool call.
Everything above the Activity is your own typed code, not a framework's abstraction.

Temporal is the only evaluated engine meeting all seven hard requirements — N-way fan-out with fan-in, human gates that pause for days, resumability without re-paying for LLM calls, per-step cost attribution, namespace tenant isolation, and genuine cross-language workers — on an MIT licence. And the elegant find: configuring its DataConverter with an encrypting payload codec plus external storage keeps all participant text out of the append-only event history, converting the otherwise-intractable "erasure from an immutable log" problem into crypto-shredding. Orchestration cost is negligible — roughly $0.35 of Temporal Actions against $1,300–2,700 of inference for a 50,000-entry study. Never optimise the orchestrator.

Data — one Postgres, and provenance as the primary key

Keep embeddings in pgvector in the same database as tenant rows, partitioned by (tenant_id, study_id). Tenant isolation is then inherited from row-level security rather than reimplemented, which structurally kills the "forgotten metadata filter" leak that OWASP names as the multi-tenant RAG failure mode. Partitioning also converts pgvector's weak post-filtering into partition pruning — decisive here, because every query in this product is filtered.

The strongest isolation control isn't a database feature

Retrieval tools must be structurally incapable of expressing a cross-tenant query. Tenant scope is injected from a signed job context — never an agent-supplied parameter. An agent that cannot name another tenant cannot leak one.

Provenance is the primary key of the system. The same edge set that produces your citations makes cascading erasure a bounded graph walk instead of an impossible archaeology project. Pair it with per-subject crypto-shredding — destroy the subject's key in KMS — and you are compliant in seconds while re-derivation runs for days, decoupling "legally compliant" from "finished recomputing."

Deliberately skip a graph database, a search engine, an OLAP warehouse, and every agent-memory vendor. Each is another store to isolate, back up, audit and erase from. On GraphRAG specifically: it's over-engineering, for a sharp reason — the multi-agent coding pipeline already is a domain-specific GraphRAG. Codes, themes and evidence edges are the graph; bi-temporal edge tables capture how culture evolves without a new store.

Correction — I had recommended Presidio

On the REDACT benchmark, Microsoft Presidio achieves 0.07 recall on high-sensitivity PII versus 0.74–0.77 for LLM-based detectors. Since redaction must happen before any model call, the corrected design is a two-stage detector: a self-hosted LLM detector in-VPC as primary, with regex/NER as a fast tripwire and backstop — never as the sole layer. This is also the strongest argument for self-hosting a small model early: you need an in-VPC model to safely redact before calling any external one.

Hosting

The verdict you asked for

Hostinger is not viable as the primary platform, and it is not close. No GPU, no managed Kubernetes, no S3-compatible object storage, no managed PostgreSQL, no KMS/BYOK, no VPC or private endpoints, and no SOC 2 Type II — with an SLA whose entire remedy is a 5% service credit usable only toward further Hostinger purchases, which alone fails enterprise vendor review.

This is a category mismatch, not a quality judgement — a competent mass-market host being asked to be a cloud platform. It does have a real role: the marketing site, docs and domains, plus non-regulated internal tooling — strictly outside the SOC 2 scope boundary, with no shared credentials and no network path to production. Use it there.

Cost shape changes the architecture

Model inference is 70–85% of infrastructure cost at MVP and can reach ~53% of COGS at scale. That makes tiered routing, prompt caching, Batch API and hard per-tenant token caps existential rather than optimisations. It also forces one amendment to the agent design: "dynamic agent spawning scaled to disagreement" is an unbounded cost amplifier and must carry a hard cap. A corpus where coders never converge would otherwise spawn without limit — cap it, and treat hitting the cap as the signal to escalate to a human.

Two legal risks nobody asked about

Surfaced unprompted by the research; both land directly on core differentiators and warrant counsel review.

GDPR Art. 9

Special-category data is unavoidable

Health, ethnicity, politics, sexuality and union membership appear routinely in transcripts and community discourse — the most valuable sources are the likeliest to carry it. Art. 9 needs an explicit lawful basis, not consent-by-default.

EU AI Act

Workplace emotion recognition is prohibited

Any sentiment or emotion feature applied to employee-adjacent data — internal Slack VoC, support agents, employee research — may be a prohibited practice, not merely a regulated one. Scope it out of workplace contexts, or out entirely.

The panel is the moat

One-off interview tools can rent a marketplace. Longitudinal ethnography lives or dies on a retained, consenting, richly-profiled panel that stays engaged for weeks or months — expensive to build, very hard to copy.

Stage 1

Don't build a panel yet

Integrate marketplace APIs plus a BYO-user intercept. Win on the AI ethnography workflow — capture → transcribe → grounded coding → cited synthesis. Ship consent-lifecycle tooling from day one as the differentiator.

Stage 2

Own the relationship

A research-hub layer so each customer builds and re-contacts their own longitudinal panel inside the product. Build the fatigue, rotation and re-consent machinery. Retention compounds.

Stage 3

Own the pool

A proprietary verified panel as premium managed recruitment — invested specifically in the B2B and specialist depth where dscout is weak.

Consent is a lifecycle, not a checkbox

Continuous observation needs continuous consent: re-consent checkpoints, per-entry share/don't-share control, frictionless withdrawal with payment for time already given, and tooling for secondary subjects — home and work video inevitably captures non-consenting third parties. Panel fatigue is now treated as an ethical harm in its own right, not merely a data-quality problem.

09Roadmap

One engine, three surfaces

Wrap the engine; don't rebuild the runtime. Every surface — web app, API, MCP server — is a thin client over the same governed core, sharing one async job contract: submit → job_id → poll → result.

Phase 0

Engine + MVP web app

One low-risk official connector → governance gate → embeddings → a small real multi-agent loop (orchestrator, 2 independent coders, κ, adversarial critic, human queue) → cited insight in the browser. Async job model and consent tooling from the first commit.

Phase 1

Depth + governance

More connectors, community and discourse modelling, the full PII/provenance/audit path with cascading erasure and k-anonymity, admin console, multi-tenant hardening, evals in CI.

Phase 2

Public API

REST for jobs, GraphQL for the insight graph, tenant-scoped keys, gateway budgets, docs and SDKs — over the same engine.

Phase 3

MCP suite

An MCP server publishing search_insights, analyze_community, detect_themes, track_behavior_trend, run_observation_study and the async job tools — with provenance and k-anonymity enforced server-side. Become the ethnographic-intelligence capability other agents depend on.
